# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Durable product and design decisions

- Product: DEGEN PENSION, a Robinhood Chain split-buy gateway. Every official gateway purchase routes the post-fee net amount 99% to the adopted project token and 1% to canonical QQQ Stock Token in one atomic transaction.
- Brand: 401KEK is the meme/editorial series, not a claim about the US 401(k) retirement product. Characters are manic raccoon “99哥” and tiny deadpan accountant “1仔”. Core line: “99% APE. 1% ADULT.”
- Selected visual source: `/Users/a7/Documents/Codex/2026-07-24/ni/.design-options/midnight-office.png`. Match its black, old-ledger cream, toxic green and rust palette; vintage financial-office editorial tone; sharp rules; dense mono labels; and oversized condensed headlines.
- UX truthfulness: this remains clearly marked as a pre-launch prototype until an official token CA and immutable gateway exist. Never fake wallet connection, quotes, transaction hashes, MarketReady status, audits, liquidity, or live deployment.
- Conversion hierarchy: lead with the meme story, identity, and social reward. Keep detailed mechanics and risk disclosure secondary. Public explanation is three beats: buy the meme, route 1% to QQQ, print the official receipt.
- Social loop: qualifying official SplitBuy events should unlock a member number, shareable retirement receipt, and a place on the public pension wall. Never invent members or recent buys before canonical data exists.
- Pre-launch behavior: never use a disabled `CA LOADING` control as the main action. Send users to the short project story and sharing action until the verified buy route is available.
- Dynamic mascot: the homepage status and raccoon stages are driven by the official project token holder count from Blockscout, with a custom index endpoint available for production. Show honest loading, empty, and unavailable states; do not substitute invented numbers. The separate pension-wall count remains based on canonical unique SplitBuy recipients.
- Mascot source of truth: the primary raccoon is the tired, deadpan office-worker holding an empty coffee cup in `public/assets/raccoon-deadpan-v2.png`. Do not replace the main character with the manic black-background ledger illustration. Alert and employed variants may appear only as later holder-count states when they retain the same deadpan cartoon identity.
- Scarcity proof: never overlay speculative member or order numbers such as `#0001?` on pre-launch artwork. Reveal numbered membership only after a canonical qualifying SplitBuy event exists.
- Mascot library: build later holder-state scenes as variants of the canonical deadpan office raccoon—same face, suit, green tie, ink linework, paper texture, and restrained palette—changing the situation rather than redesigning the character.
- Header mark: use the black/cream/acid-green `99/1` union-seal asset in `public/brand/mark-99-1-v2.png`; avoid blue app-icon styling.
- Pre-launch receipt: omit the member-count block entirely until canonical member data exists. Do not reserve a large empty panel for unavailable data.
